# E6: A rule that said `holds` and should not

A stage after E5, from a review. On 2026-11-26 seven readers went over the repository, each
for one aspect (`research/review-2026-11-26/`, out of Git). The reader of `src/model` proved
two ways in which a rule of a team's own said `holds` of a model that breaks it. Fable and
Astra planned the mend apart, Fable tried it in a copy, and Astra read the trial and found a
third way. The owner said on 2026-11-27: "yes broken is fine, implement it". Built by the main
session.

**After it** a rule finds a way that comes back to its start, and no rule is judged while a
record of the architecture has an error. `seefore remove`, a change held on a check and
`seefore apply` refuse and allow what they did before.

## What was wrong

| Case | What the check said | Now |
| --- | --- | --- |
| `never: {way: {from: {id: app-api}, to: {id: app-api}}}`, and the API calls the web app, which calls the API; or the API has a connection to itself | `holds`, 0 pairs | `broken`, with the way |
| `never: {from: {kind: browser}, to: {kind: database}}`, and a connection of the web app with `to: store-ordres`, a mistyped id | The error of the id, and `holds` | The error, and `not-judged` |
| A rule in `rules/app-api.yaml` beside `apps/app-api.yaml`. The id then names no record, the one error is at the rule's file, and a good rule that bans a connection to the API finds none | `holds` | `not-judged` |

## A way may end where it began

E1 said: "A way is connection after connection." It has one connection or more, and it may
end at the thing it started from.

- **Every rule of ways sees such a way**: `never`, and `each` with `through`. It is seen
  where the rule names one thing at both ends, where the two ends choose it by different
  keys, and where an end is left out.
- **A thing that nothing leads back to does not reach itself.** A way of no connection is no
  way.
- **A person and an outside system may begin a way back and be its end.** A way still does
  not go on past one, so no way comes back by passing through one.
- **All ways back to one start are one pair**, and the shortest is the one shown. `through`
  and `debt` are of it as of any way.

**One rule of the study changed its verdict**, and the owner took it. In the model of
Teleport, "Every way from outside Teleport to a resource passes the Proxy or a Relay" has
`from: {not: {within: system-teleport}}` and a list of resources in `to`. The Kubernetes
clusters are outside Teleport and are a resource. They send changes to the operator, and the
operator holds a leader lock in them: a way from outside to a resource that passes neither.
The rule is `broken` there now. So E1's line that the study's rule files "get the verdict its
own checker gave" does not hold of this rule any more.

## No rule is judged while the architecture has an error

E1 said: "Rules are judged only when every other file reads." Now also: only while no file of
the architecture has an error of a rule of the check, such as `reference-unknown`, and none
has an id that another file holds too.

- **A file of the architecture** is one outside `rules/`, `context/`, `changes/` and
  `reviews/`. A faulty rule, and a faulty line of context, leave the rest judged, as before;
  so does a warning.
- **An id that two files hold names no record**, so a selector that names it finds nothing.
  Where one of the two is of the architecture, no rule is judged.
- **Each rule is then `not-judged`**, with nothing it looked at and no debt said. The run
  ends "3 rules of your own: 3 not judged.", and the page shows the orange dot and E2's
  sentence, "No rule is judged while another file has an error", which is now what happens.
- **The counts are as they were**: given whenever every file reads.

## Two readings held against each other

`seefore remove` reads the model with and without the records, and a change is held by
reading the model as it is and as it would be. A problem in the second reading alone is
laid on the removal or the change.

- **Both readings keep what the rules find, also while their rulings are withheld.** These
  are no problems of the model: the check, `--json` and the page do not give them.
- **Why.** With a mistyped id in one record and a rule broken by another, the rule is not
  judged. Taking the mistyped record away makes it judged, and its break would look new: the
  removal was refused, and a change that mended the id was told the break as its own. Tried
  in the copy before this was built.
- **So nothing changes for the three verbs**: they compare what they compared before this
  stage. A change that mends an id, and by that makes a break, is still told it.

## What is out

- **A file that does not read still hides a break** from both readings, and the break is
  laid on what makes the model whole. The review's third finding there; not mended here.
- **A break of a way is compared by its words**, which name the shortest way. Removing the
  shorter of two ways that break a rule is refused, since the same break then names the
  other way. Found by Astra, true before this stage.
- **The page's sentence names no file.** Astra would have it say that an architecture file
  has an error and point at `seefore check`; E2's sentence is kept.
