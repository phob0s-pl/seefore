A stage after H1. The design skills said "Read no code". On 2026-11-26 the owner asked that
they read it where it lies in the workspace, "in smart way: its review points should also be
only about architecture and things we will change in arch not in code", and "the same for
feature designing". Fable and Astra planned it apart, and two trials were run
(`research/code-in-reach/`, `research/experiments/r1` and `r1c`, `plan4.md`: all out of Git).

**After it** `/seefore:change` looks at the code before it asks, for the facts its draft leans
on. One reader of `/seefore:review`, `plain`, reads the code, and the joiner opens what it
cites before it keeps a point. Nothing of the tool changes: no key, no check, no guide.

## What is in reach

| The code of a part that | Is in reach when |
| --- | --- |
| Names no repository, by itself or by its system | The folder above the model's, or the model's own where code lies in it beside the records, holds build files, deploy files or folders of code. A folder of several projects is not it |
| Names a repository with `workspace: true` | The folder of its `name` beside the model's folder has files. With none: "`<name>` is not here: I could not look" |
| Names a repository without the flag | For `change`, only where the person named its folder in the session. For `review`, which asks nobody, never. It is not looked for |

`seefore guide repositories` says of the last "one of the folders the session can read". These
two skills take the narrower reading: a folder is tried only where a record or the person
says where it is.

## The line it holds

- **No place of the code is stored**: no file, folder or line in a record, a change or a
  review. A place lives in one last message. `seefore check` opens no folder but the model's.
- **A point or a line from the code is of the design**: "which record, step or line of this
  change would be different for it?" A fault of the code alone is a line of a message.
- **Nothing is mended quietly.** Where the code shows a record otherwise, the record stays,
  and the last message says so and names `/seefore:model`. No "only" or "none" from a search.
- **H1 said of `change` and `review` that they read no code.** This stage changes that for
  those two and `plain`. `context`, `answer`, `model`, `flows` and the second reading do not.

## The runs on these texts

Two runs on 2026-11-27, the plugin as this stage has it and the command of `main` at
`ba54a06`, for 2.49 US dollars. No bar: they say whether the texts work.

- **One whole review**, of r1's seed that builds a second holder. The joiner handed `plain`
  two folders in reach and two repositories not in reach, and the other readers no line. It
  opened four files of the code before it kept the two points that rest on it: both are
  known faults of the seed and blocks of the review, which has nine points and no place.
- **One draft by `change`**, of the prompt that turns on the changed hop. It looked before it
  asked, and again after the answer. **It still rested on the false premise, and wrote it as
  read**: it opened the function that marks a miss and named the part the model names, and
  did not open the file that starts that part. r1c's draft had this right: of two drafts
  with the code, one. The sentence against this is sharper now, and untried.
- **So `change`'s number is of the tried text.** The four prompts are to be run on this one
  before it is trusted: six runs, the first trial of `plan4.md`.
