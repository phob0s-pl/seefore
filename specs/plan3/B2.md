# B2: The skill `model`

Stage B of `plan3.md`, as the owner set it on 2026-11-25: five rounds on Syncthing, Teleport,
Sentry, Home Assistant and GitLab. A round is five runs by Opus at medium effort, one a
repository, and one review by Fable against the code. Runs, keys and reviews stay out of Git.

**After it** a person types `/seefore:model` in a repository and gets its parts, stores and
connections: each running part with the file that starts it, each connection with the file
that shows it. In a large repository `/seefore:model --parallel-agents=4` reads more of it.

## The skill

`plugin/skills/model/SKILL.md`, 120 lines, with `seefore guide model` put in as it loads.

| # | Its rule | The fault it answers |
| --- | --- | --- |
| 1 | An app is code that runs apart: which file starts it? What a deploy file or config starts under another command or role is an app for each; a subcommand is its program; a part built elsewhere and pinned here is an app | Nine subcommands and tools written as apps; five pinned parts written as systems |
| 2 | A store is data that others reach by an address. Of a broker, each topic or queue | A broker as one store, with 16 connections ending at it |
| 3 | A connection needs a file from this session where this app names the far end; its path goes in `source` | About 62 of 180 connections rested on no file |
| 4 | Write what the files show, not what is remembered of the project | A topic that no file names |
| 5 | Every app, store, component and piece of infrastructure names its `source` | |

**Its steps**: `seefore list`; find what runs, from build and deploy files, entry points and
config, in at most 120 files; find what each app talks to; write the records; `seefore check`,
mended three times at most; hold every app against rule 1 again; say what was left unopened.

**With several agents**, only when the person types `--parallel-agents=<n>`. A1 gave no skill
other agents; the owner asked for them on 2026-11-25, for `model` alone.

- **The frame.** The session writes every record but connections, and runs the check.
- **The parts.** It cuts the apps with code here into at most `<n>` groups of neighbours, a
  very large app by its folders, and starts one agent a group, all at once. An agent sees
  nothing of the skill, so the text holds what each is told, whole. An agent writes only
  connections that start at its own apps, and ends with lines for what it found and may not
  write: `MISSING`, `INTO`, `UNREAD`.
- **The join.** The session itself, when all have ended: each missing store and system once,
  then the connections the lines name. It alone writes a new part, so none stands twice, and
  its last message names each line it left out.

## What the tool gained

| What | It does |
| --- | --- |
| `source` on a connection | One to three files where the code or config of `from` names `to`. A path that is gone is the warning `source-gone`; a folder is the warning `source-folder` |
| A count in the check | "3 stores or components that no connection names: …", after the problems. A count and no warning, so that no connection is written to quiet it |
| `seefore remove <id>...` | Takes records away. It refuses, and removes nothing, while a record that stays names one of them, and says which. `--dry-run` |
| `seefore list` | "No records yet." on an empty model; "Not listed, since it has an error: …" for a file that is no record |
| `seefore check` | With no problem it says what it held. With errors it says in one line what it did not count |
| `seefore guide <skill>` | Says where the folders lie, and tells a key that folders share once, "as in people.": 255 lines for `model` where 311 were |
| The guide's words | Of 43 faults the reviews found, 36 are mended: `only`, `kind`, `opens`, `source`, a store's `in`, what an app is, a broker's topics, a mail relay, and the check's messages for a list and for a key of one value |

## Covering a whole repository

- **One session is the default**, and enough under about a thousand files or ten apps. On a
  large tree it finds every app and what the deploy files name: about six items in ten.
- **`--parallel-agents=4` for a tree of thousands of files**: 82% of the items where one
  session finds 62%, twice the connections, for 2.3 to 2.7 times the dollars and 1.2 to 1.6
  times the minutes. The skill's last message offers it when many folders stayed unopened.
- **`=8` only above about twenty-five apps with code**: one trial, each gain at twice the price.
- **The session itself joins; there is no merging agent.** It holds the frame, every id and
  every report, which an agent would have to be told. Rounds 4 and 5 have no second record.
- **Unfound in both forms**: files and folders on a host's disk, the depth of one very large
  app, what a part with no code here writes, owners. The last message names what was left
  out and not opened; the person runs `/seefore:model <folder>`, or writes the record.
- **Not measured**: the skill on a folder, a mend of a model that is there, a merging agent.
