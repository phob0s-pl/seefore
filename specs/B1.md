# B1: Basic modelling

Stage B1 of `plan2.md`. It takes over the format we had and the code that reads it, and cuts
the code, not the format. The owner approved it on 2026-11-23, after the format was checked
again against the eight trial models and every research note (`research/modelling/`, out of
Git; the numbers M1 to M15 below are its choices). Builder: Sonnet.

## What you can do after it

Run `seefore --server --workdir=<your model>` and see the model's name, how many records of
each kind it has, and every problem in its files: the file, the line, what is wrong and how
to mend it. Point an editor at the schemas in `schema/` and have it check a record as you type.

## The format, as it was built (M1)

A folder with the marker `seefore.yaml` (`format: 1`, and a `name` of one line) and one YAML
file a record, `<folder>/<id>.yaml`. The folder is the kind and the file's name is the id.

| Folder | What a record is |
| --- | --- |
| `people/` | A kind of person who uses the software, runs it or takes part in an exchange |
| `systems/` | Software its users see as one whole, ours or somebody else's |
| `apps/` | Code that runs as a unit of its own: started, deployed or scaled apart from the rest |
| `stores/` | Data that others read or write: a database, files, a cache, an index, a queue, a topic |
| `components/` | A responsibility inside one running app. It runs only as part of that app |
| `connections/` | One thing acts on another, for one purpose |
| `infrastructure/` | A thing whose whole job is to pass exchanges on |
| `owners/` | The team, role or organisation that answers for a part |
| `technologies/` | A thing with a name that a part is built with or an exchange is carried in |

- **The thirteen fields stay**: `name`, `description`, `in`, `kind`, `external`, `technology`,
  `owner`, `from`, `to`, `via`, `only`, `access`, `opens`. Required are a name, what a thing is
  in, and the two ends of a connection. **A connection's name may be left out** (M13).
- **An id** is lowercase letters and digits in groups joined by single hyphens, a letter first,
  80 at most. It names one record in the whole model (M2), is given once, and is never changed
  or given to another thing. A connection keeps its id while it is the same exchange.
- **Strict YAML**: one mapping; no comment, anchor, alias, tag or key twice.
- **The reader takes any legal layout** (M14). The order of keys is a writer's form, not a rule.

## What is in

- **Reading, in `src/model/`**: the texts of the files go in; records and problems come out.
  It is taken from `.old/packages/core/src/` and cut. `yaml` and `zod` are added.
- **One definition of the format**: `zod` shapes that carry each kind's and field's definition
  in words, with C4's own words, "container" and "relationship", beside ours.
- **A JSON Schema for each kind and for the marker** (M6), written from the shapes into
  `schema/` by `npm run schema`. A test holds the files to the shapes, and tries them on a
  good record and on bad ones. An editor binds them by folder, since a record holds no
  schema line.
- **The problems of one file**: a key not known, a key missing, a value of the wrong kind, an
  id not allowed, YAML not allowed, a marker that is wrong, a format that is not 1. Each has
  the shape of A3 and a line that says how to mend it. A broken file leaves the others read.
- **A problem has a severity**: `error` or `warning`. B1 has one warning: a YAML file in a
  folder that is not one of the nine. It is never an error and never silent.
- **`/api/model`** answers with the name, the records and the problems.
- **The page** shows the name, a count for each kind, and the problems as a list.

## What is out

- **Everything across records**: an id twice, a reference to nothing, a thing inside the
  wrong kind of thing. That is B2, with the `check` of a model.
- **Looking for the model above or below the folder given**, a marker under another
  spelling, a model inside a model, links. The folder given is the model, or one line says
  that it is not.
- **What a part takes from what it is in** (an owner, a condition), with its source: B5.
- **An index of the model for agents**: milestone 8. **The records one by one**: B5.
- **Groups, named conditions, other names, a kind `library`** (M4, M5, M15): later, each as
  an optional key or a new folder, which breaks no file.

## Tests, about twelve

A small good model reads, with its count for each kind. One test each for: a key not known,
a key missing, a wrong value, a bad id, a comment, a marker with no format, a format that is
not 1, a file in a folder that is not known. A broken file leaves the others read.
`/api/model` answers with records and problems. The schemas match the shapes, pass a good
record and refuse a bad one.

## The try

On the private model and on one public trial model: the number of records is the number the
old command gives, and there is no problem. The old command still runs from `.old/`.
