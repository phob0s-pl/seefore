# E1: Rules of a team's own

Stage E1 of `plan2.md`: a team writes what must hold in its architecture, and `seefore check`
judges each rule from the model's files alone, with no AI and no code read. The study is in
`research/rules/`, out of Git; the owner took its six recommendations on 2026-11-24 and said
to build. Builder: Opus. Review: Fable, the main session. The page is the next stage, E2.

## A rule

After it you write a rule in `rules/<id>.yaml`, the thirteenth folder, run `seefore check`
and read what breaks it. It is read as a record is: one id space, strict YAML, a JSON Schema.

| Key | What it means | Needed |
| --- | --- | --- |
| `name` | The rule in words: one sentence a person reads. One line, 1 to 200 characters | yes |
| `description` | Why it is a rule | no |
| `never` | A selector. Nothing that it chooses may be in the model | this, or the next two |
| `each`, `must` | Two selectors. Each record that `each` chooses also matches `must` | |
| `debt` | Ids of records that break the rule and stand for now | no |

    name: A seat is held or sold only in Inventory
    each: {to: {id: [holds-store, inventory-database]}}
    must: {from: {id: inventory}}

    name: The frontend calls no system outside
    never: {from: {id: frontend}, to: {external: true}}

    name: Every way from a person to a database passes the API
    each: {way: {from: {kind: people}, to: {kind: database}}}
    must: {through: {within: api}}

## The selector

It chooses among the records of the other twelve folders. Every key given must hold. A list
means "any of". A key that a record's kind does not have does not match it.

| Key | Chooses |
| --- | --- |
| `id` | The record with this id |
| `kind` | By folder (`stores`, `features`) or by the record's own kind (`database`, `browser`) |
| `within` | A thing, with everything in it at any depth |
| `not` | What the selector given here does not choose |
| `owner`, `technology` | An id, `any` or `none`. An owner is its own, or that of what the thing is in |
| `external` | `true`: an outside system, or a thing in one. `false`: any other thing |
| `only`, `name`, `description`, `opens` | Whether it is there: `any` or `none`, and `opens: to`. Never by its words |
| `from`, `to` | Of a connection: a selector that this end matches |
| `via` | Of a connection: a selector that one hop matches, or `any`, `none` |
| `access` | Of a connection: `read`, `write`, `read-write`, `any` or `none` |
| `data` | Of a connection: data that a step of a flow passes on it, or `any`, `none` |
| `connection` | Of a thing: it is an end of a connection that this selector chooses, at the end the selector leaves open. So a rule can ask that a connection is there |

## A way

In `never` or `each`, `way: {from: …, to: …}` chooses ways. Of a way, `must` holds `through`.

- **A way is connection after connection**, each starting at the thing where the one before
  ended. It passes its start, its end, the things between, and every hop in `via`.
- **It turns only at an end**, never at a hop, and never goes on past a person or an outside
  system. It does not go down into a thing, nor on from a queue to its readers.
- **An end left out is any thing.** `never`: no way leads there. `each`: every way passes a
  thing that `through` chooses.

## In the check

- **A broken rule is an error** of the rule `rules/<id>`, one problem a record, at the record
  that breaks it: "`door-list-export-reads-tickets` breaks the rule `venue-databases`: A
  database of the Venue team is reached only by that team's own parts." Of a way: at the
  rule's file, one problem a start, with the shortest way and the connections it goes by.
- **No rule passes in silence.** A key that is not known and an id that names no record are
  errors, by the rules there are, as is a fault of form (`rule-shape`), and the rule is not
  judged. `each`, `from`, `to` or `through` that chooses nothing is a warning,
  `rule-looks-at-nothing`; so is a rule over `data` where no flow walks a connection.
- **`debt`**: a record named there may break the rule: it is counted, and a new break still
  fails. Of a way, `debt` names connections, and a way does not go by one. A debt that
  breaks nothing any more is a warning, `debt-paid`.
- **Rules are judged only when every other file reads.** A faulty rule leaves the rest judged.
- **The run ends**: "14 rules of your own: 12 hold, 2 broken. 2 of debt." `--json` and
  `/api/model` give each rule's state, what it looked at, what breaks it and its debt.

## What is out

- **Rules on the page**: E2. The page stays as it is, and shows no rule in any list.
- **Later**: a count ("one writer at most"), the order of steps in a flow, "the same owner
  as the other end", named groups, a rule that chooses steps.
- **For good**: a language of expressions; rules over words; how data is kept, sealed or plain.

## Tests, about twelve

A model with a rule of each form has no problem, and `test/shop` gets a rule. One test each
for: `never` broken, at the record; "only X does Y"; a way that passes `through` by a hop,
and one that does not; a way that stops at a person and turns at no hop; an end left out;
`connection` in `must`; an owner taken from above; data from a step; `debt` and a debt paid;
a key not known and an id that names nothing; a fault of form; a rule that looks at nothing;
no rule judged when another file does not read; the last line and `--json`; the schema.

## The try

As it went: the study's 223 rule files, of seven public systems and the private one, get the
verdict its own checker gave, with the same number of breaks; two of them after "from
anything" became an end left out. The page's lists hold on a model with 27 rules.
