# A3: Code architecture

Stage A3 of `plan2.md`. It is a stage that defines: this page is its result. Fable wrote it
and Astra reviewed it, and the owner approved it, on 2026-11-23.

## What you can do after it

Start A4 knowing the folders, the tools and the borders between them. Later stages add to
these and do not choose again.

## The shape

One npm package with three folders of source. Each folder uses only what the table allows.

| Folder | What it does | May use |
| --- | --- | --- |
| `src/model/` | The records, reading them from text, the rules, and what a view shows | `yaml`, `zod`. No Node, no browser |
| `src/server/` | The command: reads the files, serves the model and the page | `src/model/`, Node |
| `src/ui/` | The page: the diagram, its layout, the lists | `src/model/`, React, `@xyflow/react`, `elkjs` |

- **The server and the page do not use each other.** They meet at one address, `/api/model`,
  and the type of its answer is in `src/model/`.
- **Two things hold the table.** Each folder is type-checked with its own settings, so the
  model sees neither Node nor the browser. And one test reads the imports of each folder.

## How the data goes

1. **The server reads** the YAML files of `--workdir` with `src/model/`, anew at each request.
   That gives records and problems. It listens on this machine only.
2. **The page asks** `/api/model` and gets both. A reload shows an edit.
3. **The page works out** what a view shows with one function of `src/model/`: records and a
   request go in; ids, ends and what is inside what come out. It lays that out with ELK in a
   worker of the browser, and draws it.

- **Everything is found by its id, a connection too.** Two connections can join the same two
  boxes, and a step of a flow must light the right one.
- **A problem has one shape**, which a person and an agent can both act on: the file, the
  line, the rule's id, the record's id and field where known, what is wrong, how to mend it,
  and a second place where two records clash.
- **The server keeps nothing and lays nothing out.**

## The tools

| For | Tool, as of 2026-11-23 | Why |
| --- | --- | --- |
| The language | TypeScript 7, strict, with only the syntax Node can strip | Node runs the source as it is |
| Running | Node 24 or newer | The first line in which running TypeScript is stable |
| Reading and checking | `yaml` 2, `zod` 4 | The old work used them, so its code can be taken over |
| The page | React 19, `@xyflow/react` 13, `elkjs` 0.12, plain CSS | The same |
| Building the page | Vite 8 | A change shows at once while the page is worked on |
| Tests | Vitest 5, set up in Vite's own file | One setup for both |

- **`npm run check`** checks the types of each folder, runs the tests and builds the page. It
  prints its time; over 30 seconds is a fault to mend before the next stage.
- **`npm run dev`** starts the command and Vite, and Vite passes `/api` on to the command.
- **The command runs from the source.** `bin/seefore.js` starts Node on `src/server/main.ts`.
  That works in the checkout and through `npm link`. Tried here: Node refuses TypeScript
  under `node_modules`, so before anyone else installs it the command is built into one file.

## What is tested

- **`src/model/` and the server's answer**: text goes in; records, problems or a view come
  out. About ten tests a stage.
- **One test in a real browser, from B4 on.** The built page, served by the command, draws a
  known box and arrow; from C3 the chosen step lights the right arrow. It drives the Chrome
  that is installed, needs no new dependency, and stops what it starts.
- **Nothing else of the page is tested.** It is tried by opening it on two models.

## What is out

- **Workspaces, a package for the layout, a worker on the server, a store of pictures.**
- **The command built into one file**, with a try of the packed install: milestone 8.
- **Following the files as they change**, and a number for each state of them.
- **A library of ready parts for the page**: B3. **A JSON Schema written from the `zod`
  shapes**, for agents and editors: B1.
- **A linter and a formatter.**

## Choices to approve

1. **One package with three folders**, where the old work had four packages.
2. **The layout runs in the page.** The price: every browser lays out anew, and the command
   has no finished picture to give. Node can still run ELK on the same graph, to measure.
3. **The old tools stay, and Vite is added.** The owner's present UI uses Vite too.
4. **The command runs from the source for now.** A build comes before the first install
   anywhere else.
5. **One test in a browser, and no other test of the page.**

## What Astra's review changed

Astra first wrote its own outline, unseen: the same three folders, the layout in the page,
the same tools. Then it changed five things in the draft:

- **Running from the source fails in a real install.** Tried by both; the limit is named.
- **One test in a browser**, where the draft had none: a built page can pass every other
  test and draw nothing if the worker's file is not served.
- **Each folder is type-checked with its own settings**, where the draft had one run.
- **No number for the state of the files.** The server reads at each request.
- **A connection has an id, and a problem names the record, the field and a second place.**
