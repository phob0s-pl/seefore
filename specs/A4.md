# A4: Minimal command

Stage A4 of `plan2.md`. It builds the skeleton that `specs/A3.md` describes and nothing of the
format. The owner approved it on 2026-11-23. Builder: Opus, since it sets the structure.

## What you can do after it

Run `seefore --server --workdir=<dir>` on the folder of a model, open the address it prints,
and see a page that says which files it read. Run `npm run check` and see it pass in well
under 30 seconds.

## What is in

- **The package**: `package.json`, the three folders of A3 with their own type settings,
  Vite's file with Vitest set up in it, `bin/seefore.js`.
- **The command** has three options and no verbs yet:

  | Option | What it does |
  | --- | --- |
  | `--server` | Serves the page and `/api/model`, on this machine only, and prints the address |
  | `--workdir=<dir>` | The folder to read. Without it, the folder the command is run in |
  | `--port=<n>` | The port. Without it, 4400 |

- **`/api/model`** answers with the names of the YAML files under the folder, each relative
  to it, and an empty list of problems. It reads anew at each request.
- **The page** shows the folder's name, how many files were read and their names. With none
  it says "No files." A reload reads again.
- **What goes wrong is said in one line, and the command ends with 1**: a folder that is not
  there or cannot be read, a port that is taken, an option it does not know.
- **`npm run check`** and **`npm run dev`**, as A3 has them.
- **`npm link`**, so that `seefore` on this machine is the new command. The old one stays in
  `.old/` and can be run from there.

## What is out

- Reading what is in a file: B1. Rules and the `check` of a model: B2. The diagram: B4.
- Opening the browser, following the files, a build of the command into one file.
- Any library of ready parts, any styling beyond a readable page.

## An example

    $ seefore --server --workdir=models/shop
    seefore: 14 files read from models/shop
    seefore: http://127.0.0.1:4400

    $ seefore --server --workdir=nowhere
    seefore: cannot read the folder "nowhere"

## Tests, about eight

The options read right and wrong. The files of a small folder are listed, relative and in
order. `/api/model` answers for that folder and for an empty one. The page's file is served.
A folder that is not there ends with 1. The imports of each folder keep to A3's table.

## The try

On the private model and on one public trial model: the number of files on the page is the
number that `find` gives for the folder.

## Choices to approve

1. **The command prints the address and does not open the browser.**
2. **The port is 4400 unless given.** A fixed port lets `npm run dev` find the command.
3. **`npm link` replaces the old `seefore` on this machine** at this stage, not later.
4. **Every `.yaml` and `.yml` file under the folder counts as read**, at any depth. B1 says
   which of them are records.
